- `task-service.js` — прикладные функции ПР2, DOM не трогают.
- `task-selectors.js` — `getVisibleTasks`, чистая фильтрация.
- `task-view.js` — `createTaskElement`, `renderTaskList`, `renderSummary`, `renderEmptyState`.
- `main.js` — состояние (`currentTasks`, `currentFilter`), обработчики, `renderApp`.

Полный список хранится в `currentTasks`, фильтр — в `currentFilter`. События обрабатываются делегированно на `#task-list` и `#task-filters`. Сводка вычисляется в `renderSummary` через `getTaskStats(currentTasks)` — то есть по полному массиву, а не по видимой выборке.

## Отладка и клавиатура

Точка останова в `handleTaskListClick` на строке чтения `dataset.taskId`:

- `event.target` — вложенный `span.action-label` внутри кнопки.
- `event.currentTarget` — `ul#task-list`.
- `dataset.taskId` — строка `"4"`, тип `string`.
- после `Number(...)` — `4`, тип `number`.
- выбранное действие — `"toggle"`.
- результат сервиса — `{ ok: true, tasks: [...] }`, новый массив.
- после сохранения — `renderApp()` перерисовывает список.

Клавиатура: Tab переводит фокус между фильтрами и кнопками карточек, Enter и Space активируют кнопки. После `toggle` фокус остаётся на кнопке той же задачи (`restoreTaskFocus`). После удаления карточки фокус переходит на активный фильтр.

Отказ для `777`: в `data-task-id` вручную подставлено `777`, действие `toggle` → сообщение «Задача не найдена», данные не меняются. Отказ для `4abc`: `Number("4abc")` → `NaN`, `isSafeInteger` → `false`, сообщение «Некорректный идентификатор задачи», данные не меняются. После корректного выбора фильтра карточки перерисовываются из настоящего массива, сообщение очищается.

## Вывод

В ПР3 данные (`currentTasks`) отделены от представления (DOM-карточки). Изменения выполняются через функции ПР2, после чего вызывается `renderApp`. Фильтр не удаляет записи: `getVisibleTasks` возвращает новый массив, а `currentTasks` сохраняет все задачи. Удаление только DOM-узла без обновления массива вернуло бы запись после следующей перерисовки. События обрабатываются делегированно: один обработчик на `ul#task-list` вместо отдельного на каждую карточку — это исключает накопление обработчиков при повторной отрисовке. Наиболее важная деталь — `id` читается из `dataset` как строка и проверяется через `Number.isSafeInteger` после преобразования через `Number`, поэтому `"4abc"` не превращается в `4`.
